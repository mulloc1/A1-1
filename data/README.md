# 데이터 출처와 준비 상태

## 선정한 데이터셋

- **이름:** H&M Personalized Fashion Recommendations
- **제공자:** H&M Group, Kaggle competition
- **원본:** https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data
- **이용 조건:** https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/rules
- **선정 이유:** `article_id`로 상품 메타데이터와 이미지를 연결하고, 같은 상품 ID와 `customer_id`가 있는 구매 기록으로 상품 분석과 RFM을 함께 수행할 수 있다.
- **현재 상태:** 원본 파일을 `data/h-and-m-personalized-fashion-recommendations/`에 받아 기본 적합성을 실측했다(2026-10-22). 아래 컬럼 매핑은 실제 CSV 헤더와 일치한다.

Kaggle 대회 데이터의 비상업적·교육용 이용 조건을 따른다. 원본 CSV, 이미지 및 이를 재배포하는 가공 데이터는 GitHub 저장소에 올리지 않는다. 저장소에는 분석 코드, 출처, 다운로드·재현 절차와 집계 결과만 둔다. 데이터 원본은 로컬 `data/h-and-m-personalized-fashion-recommendations/`에 보관하며 `.gitignore`로 제외한다.

### 데이터 준비

1. 위 Kaggle 데이터 페이지에 로그인하고 대회 이용 조건을 확인·수락한다.
2. 데이터셋을 다운로드해 `data/h-and-m-personalized-fashion-recommendations/`에 압축 해제한다.
3. 그 디렉터리에 `articles.csv`, `customers.csv`, `transactions_train.csv`, `images/`가 있는지 확인한다. `images/`에는 상품 ID 앞 3자리 이름의 하위 폴더가 있어야 한다.
4. 원본 파일은 Git에 추가하지 않는다. 분석용 표본과 이미지 피처는 이후 단계의 재현 가능한 코드로 로컬에서 생성한다.

## 원본 파일과 연결 관계

| 원본 | 분석 역할 | 연결 키 |
| --- | --- | --- |
| `articles.csv` | 상품명, 설명, 분류 등 상품 메타데이터 | `article_id` |

모든 `article_id`에 이미지가 있는 것은 아니다. `article_id`는 앞자리 0이 사라지지 않도록 문자열로 읽는다. 이미지 경로는 `images/{article_id 앞 3자리}/{article_id}.jpg`이다.

## 분석용 표준 컬럼 계약

### 상품 표: 상품 1행

| 표준 컬럼 | H&M 원본/계산 | 의미 |
| --- | --- | --- |
| `product_id` | `articles.article_id` | 상품 식별자, 문자열 유지 |
| `product_name` | `articles.prod_name` | 상품명 |
| `category` | `articles.product_group_name` | 상품 분류 |
| `description` | `articles.detail_desc` | 상품 설명(없으면 결측) |
| `reference_price` | 해당 상품의 구매 `price` 중앙값 | 관찰된 판매가의 대표값. 정가 아님 |
| `image_path` | `images/`의 `article_id` 대응 파일 | 로컬 이미지 경로, 없으면 결측 |
| `image_array` | 이미지 파일을 NumPy 배열로 읽은 값 | 평균·표준편차·보너스 특성 계산 입력 |

### 거래 표: 상품 구매 기록 1행

| 표준 컬럼 | H&M 원본/계산 | 의미 |
| --- | --- | --- |
| `customer_id` | `transactions_train.customer_id` | 고객 식별자 |
| `product_id` | `transactions_train.article_id` | 구매 상품 ID |
| `order_date` | `transactions_train.t_dat` | 구매 날짜 |
| `amount` | `transactions_train.price` | 원본 가격값. 통화·단위는 파일 확인 후 명시 |
| `sales_channel` | `transactions_train.sales_channel_id` | 판매 채널 |

원본에 주문 ID가 없으므로 `order_id`를 만들어 실제 주문 ID인 것처럼 쓰지 않는다. **Frequency는 고유 구매일 수**로 정의하고, 상품 구매 기록 수는 별도 지표로 보고한다. 같은 날 여러 주문을 한 경우 Frequency가 실제 주문 횟수보다 작을 수 있다는 한계를 README와 노트북에 표시한다. Recency 기준일은 최종 관측 거래일의 다음 날인 **2020-09-23**로 둔다. Monetary는 선택된 고객의 모든 유효한 구매 기록에서 `amount`를 합산한다. `price` 값은 소수로 제공되며 통화 단위가 확인되지 않았으므로 원화·유로 등 실제 통화의 매출로 표기하지 않는다.

거래 CSV에는 주문 상태나 반품 표시도 없다. 따라서 반품·취소를 판별해 순매출을 계산할 수 없으며, 결과는 **기록된 구매 가격의 합계**로 부른다. Kaggle 원본 설명은 같은 고객·날짜·상품의 중복 행이 동일 상품의 복수 구매일 수 있다고 명시하므로 단순 중복 제거를 하지 않는다.

고객 CSV에 가입일 컬럼이 없으므로 코호트는 **첫 구매 월** 기준으로 계산하며 가입 월 코호트라고 표기하지 않는다. 상품 등록일도 없으므로 최초 관측 구매일을 등록일로 대체하지 않는다.

## 표본 추출 원칙

원본 전체는 분석용으로 크므로 고객을 고정 시드로 표본 추출한 뒤, 선택된 고객의 **전체 관측 기간 거래 기록**을 유지한다. 이미지 분석용 상품은 그 거래에 등장하고 이미지가 있는 `article_id`에서 고정 시드로 선정한다. 이 방식은 RFM 합계가 이미지 가용성에 따라 줄어드는 것을 막는다.

예비 검증에서는 `customers.csv`에서 고정 시드 42로 고객 10,000명을 추출하고 그들의 전체 구매 기록을 모았다. 이 가운데 9,925명에게 구매 기록 226,767행이 있었고, 6,655명(67.05%)은 서로 다른 날에 두 번 이상 구매했다. 구매 고객의 고유 구매일 수 중앙값은 3일이었다. 표본에는 상품 45,912개가 등장했고 그중 45,800개에 이미지가 있었다. 이 규모면 RFM과 이미지 EDA의 최소 요건을 충족할 수 있다.

최종 분석에서도 고객 10,000명을 고정 시드로 추출하고 그들의 전체 구매 이력을 유지한다. 상품 이미지 EDA는 이 구매 기록에 등장한 이미지 보유 상품 중 **고정 시드로 1,500개**를 뽑아 수행한다. 이미지 없는 상품을 RFM 거래에서 제외하지 않는다. 상품 이미지는 분석에 필요한 범위만 로컬에서 읽고 고정 크기 배열로 변환한다. 원본과 표본의 카테고리 및 가격 분포 차이를 확인하고, 표본 결과를 전체 H&M 고객의 특성으로 일반화하지 않는다.

### 원본과 최종 표본의 거래 분포 비교

이슈 4 노트북에서 원본 거래 31,788,324행을 청크로 읽고, 고객 10,000명의 유효 거래 229,883행과 비교했다. 양쪽 모두 **거래 행 1개를 1건**으로 세었다. 원본 가격값 `0.02–<0.04` 구간은 원본 41.65%, 표본 41.90%였고, `Garment Upper body` 카테고리는 원본 39.49%, 표본 39.77%였다. 표시된 구간별 비율 차이는 가격에서 최대 약 0.24%p, 카테고리에서 최대 약 0.29%p였다. 이 두 분포가 비슷해도 다른 고객 특성까지 대표한다고 볼 수는 없다. 구간별 건수와 전체 카테고리 비교표는 `notebooks/analysis_report.ipynb`에 있다. 원본 가격값의 통화와 환산 기준은 확인되지 않았다.
