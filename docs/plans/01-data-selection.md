# 01. 데이터 선정과 분석 단위 확정

- 예상 시간: 8시간
- 선행 단계: 없음
- 기준: [`subject.md`](../subject.md)의 데이터셋·라이선스·RFM 요구사항
- 다음 단계: [02. 프로젝트 구조와 환경](02-project-setup.md)

## 목표

상품 정보, 상품 이미지, 구매 거래를 연결할 수 있는 데이터를 확보한다. 이후 단계에서 행 수나 연결 키 부족으로 분석을 다시 설계하지 않도록 데이터 구조와 처리 원칙을 먼저 확정한다.

**선정한 후보:** [H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data). 원본 접근과 실측 검증 전까지 최종 적합성은 미확정이다. 표준 컬럼 계약과 남은 확인 항목은 [`data/README.md`](../../data/README.md)에 기록한다.

## 작업

1. 공개 라이선스 데이터 또는 제공된 샘플을 검토한다. 원본 URL, 제공자, 라이선스/이용 조건, 다운로드 날짜를 기록한다.
2. 상품 테이블과 거래 테이블의 연결 키를 확인한다. 상품 ID와 거래의 상품 ID가 실제로 일치하는지 교집합 건수와 비율을 계산한다. 출처가 다른 데이터를 임의로 연결하지 않는다.
3. 분석 대상에 **1,000행 이상, 8개 컬럼 이상**이 있는지 확인한다. 수치형·범주형·날짜형·이미지 배열 중 **3종 이상**을 포함해야 한다.
4. RFM에 `customer_id`, `order_date`, `amount` 또는 `price × qty`가 있는지 확인한다. H&M에는 주문 ID가 없으므로 Frequency를 고유 구매일 수로 정의할 수 있는지 확인한다.
5. 이미지의 포맷, 크기, 채널 수, 누락 비율을 확인한다. 이미지 배열을 만들 때 적용할 크기·채널 규칙을 정한다.
6. 취소·반품·음수 금액·중복 주문·잘못된 날짜의 처리 원칙을 정한다. 매출과 고객 수가 달라질 수 있으므로 임의로 삭제하지 않는다.
7. 상품 EDA는 **상품 1행**, RFM은 **상품 구매 기록 1행**을 기본 분석 단위로 정한다. 두 표를 연결할 때 구매 기록이 중복 집계되지 않도록 키와 집계 단위를 기록한다.
8. 가입일이 없다면 보너스 코호트는 **첫 구매 월 코호트**로 정의한다.

## 산출물

- `data/README.md`: 출처·이용 조건·다운로드/준비 방법·원본 및 분석 표본 규모·컬럼 명세·연결 키·분석 단위
- 데이터 품질 요약: 누락률, 중복률, 연결 가능한 상품/거래 비율, 이미지 형상
- 확정된 금액·주문·기간·코호트 정의

## 완료 기준

- [ ] 필수 행 수·컬럼 수·데이터 유형·RFM 컬럼을 충족한다.
- [ ] 상품·이미지·거래가 검증 가능한 키로 연결된다.
- [ ] 데이터 출처와 이용 조건을 기록했다.
- [ ] 결측·반품·중복 및 코호트 기준을 문서화했다.

적합한 데이터를 찾지 못하면 다음 단계로 진행하기 전에 데이터 소스를 다시 선정한다.
